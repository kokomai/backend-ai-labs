# 변경 요청 센터 오류 추적

1. 실패 조건을 재현한다. 문의 ID, 요청한 화면 경로, 영향을 받은 역할, 관찰된 상태나 오류, 예상 결과를 기록한다.
2. 비슷한 정상 흐름과 입력, 실행 프로필, 포트, 상태를 비교한다. 화면 → 문의 API → 저장된 분석 상태 → 워커 → MCP `trace_screen` → 모델 순서로 확인해 처음 어긋나는 경계를 찾는다. 저장 상태가 정상이면 브라우저의 새로고침과 응답 순서를 살핀다.
3. 현재 근거를 설명하는 가설 하나를 세우고, 관찰을 추가하거나 한 조건만 바꿔 확인한다. 비동기 흐름은 일정 시간 대기보다 상태 변화를 확인한다. 가설이 맞지 않으면 새 근거로 갱신한다.
4. 확인된 원인을 수정하고 같은 재현 경로에서 결과를 확인한다. 변경한 계약의 인접 정상 흐름도 확인한다. 종료 시 [완료 검증](../change-advisor-verify-completion/SKILL.md)을 참고한다.

Superpowers의 원인 조사, 정상 패턴 비교, 단일 가설 검증, 수정 단계를 프로젝트에 맞게 적용했다. [원본 고정 리비전](https://github.com/obra/superpowers/blob/22f0b463e7a5e579904dd6211a520321035526f7/skills/systematic-debugging/SKILL.md)
