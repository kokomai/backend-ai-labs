# 화면 추적과 MCP 소스 계약

1. 대상 화면의 폼이나 버튼에서 브라우저 핸들러를 찾아 요청 URL과 파라미터를 확인한다. 같은 URL의 컨트롤러와 서비스 로직을 따라간다.
2. 에이전트의 `src/main/java/com/example/changeadvisor/LegacyScreenCatalog.java`에서 해당 화면의 경로, 앵커와 기본 모드 제안 규칙을 관리한다. 실제 코드 문자열을 앵커로 사용하고 동일 문자열이 먼저 등장하는지 확인한다. 파일 추가 시 에이전트 `build.gradle`의 `processResources`에 해당 소스가 포함되는지 확인한다.
3. 화면 경로가 바뀌면 샘플 앱의 메뉴와 카탈로그를 함께 갱신한다. 에이전트의 화면 선택·검증과 MCP 리소스 `context://legacy/screens`는 이 카탈로그를 사용한다. MCP 결과 필드를 바꾸면 서버 출력과 워커의 역직렬화를 함께 갱신한다.
4. 해당 화면으로 문의를 보내 개발자 응답의 `evidence`를 확인한다. 경로는 저장소 루트 기준이며, 줄 범위는 양쪽 끝을 포함한다. 인용 코드가 실제 파일의 해당 줄과 일치해야 한다.
5. 근거를 현업에 노출하거나 런타임에서 임의의 파일을 읽도록 범위를 확대하는 변경이 있는지 확인한다. 자세한 실행 흐름은 [스모크 검증](../change-advisor-smoke-test/SKILL.md)을 참고한다.
